# Documentation Overview

This repository contains multiple documentation sources. This file provides a short map to help contributors and maintainers find the right doc and know what each file covers.

## doc/ (legacy / detailed notes)
- [API_Doc.md](doc/API_Doc.md): API reference and endpoint notes.
- [Part1.md](doc/Part1.md): Project background and goals.
- [Part2_Implementation_Plan.md](doc/Part2_Implementation_Plan.md): Implementation plan and milestones.
- [Part2_Search.md](doc/Part2_Search.md): Design for search features and indexing.
- [Part4_Validation.md](doc/Part4_Validation.md): Validation system design and notes.
- [Setup.md](doc/Setup.md): setup steps and environment details.
- [Stack.md](doc/Stack.md): technology stack and rationale.
- [Issue.md](doc/Issue.md): known issues and troubleshooting notes.
- [Knowledge.md](doc/Knowledge.md): knowledge-base and research links.
- [Ques.md](doc/Ques.md): collected questions and decisions.
- `doc/docs/` contains deeper topic docs (e.g. PART3_AI_GENERATION.md).

## docs/ (current project docs)
- [API_Doc.md](docs/API_Doc.md): API notes (may overlap with `doc/API_Doc.md`).
- [PART4_VALIDATION_SYSTEM.md](docs/PART4_VALIDATION_SYSTEM.md): Validation system (updated copy).
- [PART5_CHAT_INTERFACE.md](docs/PART5_CHAT_INTERFACE.md): Chat interface design and UI notes.

## How to contribute docs
- Add or update markdown files under `docs/` for major, polished documentation.
- Use `doc/` for working notes, drafts, or long-form planning that will later be moved into `docs/`.
- Open a pull request and reference any related issue; include a short summary in the PR body.

## Useful commands
- Open the repo root README for quick start: [README.md](README.md)
- To preview docs locally, you can use any markdown viewer or serve a documentation site (optional).

If you want, I can also:
- move selected documents from `doc/` into `docs/` and update cross-links,
- create a docs site scaffold (MkDocs / Docusaurus) — tell me which option you prefer.
